## B1 — Emergency/migration routes (security) — FIXED

`src/routes/auth.js`

- **Deleted** `GET /api/auth/emergency-debug` (was unauthenticated, leaked
  user emails) and `GET /api/auth/emergency-login/:token` (created/logged-in
  Leon's owner account with a hardcoded password; module-level used-flag

  expiry constant, and every hardcoded password are gone from the file
  (verified by grep: no token value, no password literal remains).
- **Kept** `migration-export` (line 475), `migration-import` (line 504),
  `migration-cleanup` (line 601) — the 30-min backup/self-heal depends on

    unset; **403** on a wrong token.

  password blocks in import (line 588) and cleanup (lines 630/637):
  passwords come only from `OWNER_SEED_PASSWORD_LEON` /
  `OWNER_SEED_PASSWORD_MICHAEL`, hashed with the app's bcrypt cost-12
  helper; when the variable is unset, creation is **skipped** with a logged
  warning and the route reports `{ status: 'skipped_no_password' }`.
  No password is ever invented.
- `backup_manna.py`
  (`~/workspace/goals/faithshield-and-angel-warriors-marketing-funnels/hidden_files/manna_backup/backup_manna.py`):
  no longer parses the token out of `auth.js`. It reads

  empty. A **new** token value was generated into that file (permissions
  0600; the value is not recorded here or anywhere in this log).
